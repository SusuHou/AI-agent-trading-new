# 03_Code

This area preserves the complete, reproducible workflow used to transform data, run analyses, and create research outputs.

## 1. What to put here

- `cleaning/` — scripts that convert raw data into documented processed data.
- `analysis/` — statistical, econometric, simulation, or model-analysis scripts.
- `plotting/` — scripts that generate charts and figures.
- `notebooks/` — exploratory or documented computational notebooks.
- `outputs/` — code-generated tables, logs, model summaries, and intermediate results.
- `figures/` — chart and figure files generated by recorded scripts.

## 2. What NOT to put here

- Temporary scripts that are unreadable or cannot be reproduced.
- Scripts mixed into raw-data folders.
- Final images without the code and inputs that generated them.
- Machine-specific secrets, passwords, API keys, or access tokens.
- Unexplained manual edits to generated results.

## 3. Principles of use

- The purpose of this area is not simply to learn programming; it is to preserve a reproducible processing workflow.
- Each script should state its inputs, outputs, dependencies, and intended execution order.
- Prefer small, clearly named steps over one undocumented script that performs everything.
- Keep exploratory work separate from the scripts used to produce reported results.
- Record random seeds, package versions, model settings, and computing requirements when they affect results.
- Every reported table or figure should be reproducible from documented data and code.
